# 人外ノ閨 サイト構築仕様書（段階A：語りブログ）

Nov 5, 2026 · @ぬ

## 概要

「人外ノ閨（じんがいのねや）」は、人外好きが人外好きのために作品を選んで語る、成人向けのブログです。キャッチコピーは「ヒトでは満たされない夜に。」、サブコピーは「人外好きが、人外好きのために選ぶ。」です。

サイトは2段階で作ります。この仕様書は**段階A**だけを扱います。

| 段階 | 時期 | 中身 |
| --- | --- | --- |
| 段階A：語りブログ | アフィリエイト承認前（今） | 記事が主役。ジャンル解説・語り・レビュー、YES/NO診断、コメント。アフィリエイトリンク・作品画像・価格はなし |
| 段階B：作品紹介サイト | 承認後 | 段階Aの記事はそのまま残し、作品データ（DMM API）、作品カード、セール・ランキング、PR表記を足す |

見た目と動きの正解は、試作サイト（`docs/prototype-a.html`）です。仕様書と試作で食い違うところがあれば、仕様書を優先してください。どちらにも書いていないことで迷ったら、勝手に決めずに質問してください。

## コンテンツのデータ設計

記事・ジャンル・診断はすべてファイルで管理し、管理人がファイルを直すだけでサイトに反映されるようにします。試作にある記事31本、診断28個の文章は、この形式に移し替えてください。

### 記事（`content/articles/<slug>.mdx`）

```markdown
---
title: 都市伝説・怪異の魅力：日常の隣にいる「何か」に見初められる
slug: kaii
category: genre            # guide / genre / talk / matome / review
genres: [kaii]
publishAt: 2026-11-20      # この日の0時（日本時間）に公開
description: 八尺様のような、条件がそろうと現れる正体不明の存在。…
eyecatch: /images/eyecatch/kaii.webp   # なければ仮イラスト
authorNote: 閨の主のいちばんの推しジャンルです。…      # 「閨の主のひとこと」
---
本文…
<Diagnosis id="g_kaii" />
<Figure src="/images/kaii-1.webp" alt="…" caption="…" />
<WorkBox title="…" circle="…" format="同人誌" url="公式ページURL" />
```

- 記事の中で使える部品は `Diagnosis`、`Figure`、`FigureRow`、`WorkBox`、`Callout`、`Scale`（獣度のものさし）、`Axes`（3つの軸の図）です。
- 目次は本文の `##` 見出しから自動で作ります。
- `authorNote` がある記事は、「まとめ」の直前に「閨の主のひとこと」の枠を自動で入れます。

### 予約公開

`publishAt` が未来の記事は、一覧・検索・関連記事・サイトマップのどこにも出しません。記事ページを直接開いても404にします。毎日0時0分（日本時間）にサイトを再生成して、その日の記事が自動で公開されるようにしてください。運用は「1日1本、レビューを優先して解説と混ぜる」予定です。

### 記事の種類（`categories.json`）

入門ガイド（guide）、ジャンル解説（genre）、語り・考察（talk）、おすすめまとめ（matome）、作品レビュー（review）の5種類です。

### 系統とジャンル（`genres.json`）

5系統・20ジャンルです。各ジャンルには、slug、名前、「良さ」の一文、仮イラストの種類を持たせます。

| 系統 | ジャンル（slug） |
| --- | --- |
| 獣・動物系 | 獣人（kemono）、鳥人・ハーピー（bird）、竜人・爬虫類人（reptile）、蟲人（insect） |
| 幻想・神話系 | 竜・ドラゴン（dragon）、人魚・水棲（merfolk）、悪魔・天使（demon）、吸血鬼（vampire）、神・神獣（god）、異種族（エルフなど）（ishu） |
| 和風・怪異系 | 都市伝説・怪異（kaii）、鬼（oni）、妖怪・あやかし（yokai）、幽霊・霊体（ghost） |
| 人工物系 | 機械・ロボット（machine）、人形・ゴーレム（doll） |
| 異形・その他 | モンスター・クリーチャー（monster）、スライム・不定形（slime）、植物・菌類（plant）、宇宙人・異星人（alien） |

### 診断（`content/data/diagnoses/<id>.json`）

すべて「点数方式」です。全員が同じ設問に答え、「はい」「いいえ」ごとに各結果へ点数が入ります。

```json
{
  "id": "grp_wafu",
  "title": "あなたの和風・怪異系診断",
  "chartLabel": "ジャンルごとの相性",
  "options": [
    { "key": "kaii", "name": "都市伝説・怪異", "short": "怪異", "image": "kaii",
      "description": "…", "link": "/articles/kaii", "linkText": "…の解説記事を読む", "genres": ["kaii"] }
  ],
  "questions": [
    { "text": "相手の正体は、分からないままのほうがゾクゾクする？",
      "yes": { "kaii": 2 }, "no": { "yokai": 1, "oni": 1 } }
  ]
}
```

| 診断 | 設問数 | 結果の数 |
| --- | --- | --- |
| 入門ガイド：人外の入り口診断 | 8 | 7ルート |
| 獣度診断 | 6 | 4（3段階＋変身もの） |
| 作られた存在タイプ診断・怪異タイプ診断 | 各6 | 各5 |
| 系統別診断（5個） | 6〜7 | 系統内の全ジャンル（4・6・4・2・4） |
| ジャンル別タイプ診断（19個） | 5 | 3タイプ |

### そのほか

- `carousel.json`：トップのスライド（記事slug、ラベル、一言）。初期値は入門ガイド、獣人特集、怪異・ホラー特集、おすすめまとめの4枚
- `site.json`：サイト名、キャッチコピー、自己紹介文、人気記事のslug、5件、XのアカウントURL

## ページ構成とルーティング

段階Aで作るページは次のとおりです。各ページのタイトルは「ページ名｜人外ノ閨」、トップだけ「人外ノ閨｜ヒトでは満たされない夜に。」にします。

| URL | ページ | 主な中身 |
| --- | --- | --- |
| `/` | トップ | ヒーロー、特集スライド、新着記事（最新1本を大きく＋8本）、「すべての記事を見る」、サイドバー |
| `/articles/[slug]` | 記事 | 目次、本文、診断、作品の枠、閨の主のひとこと、書いている人、関連記事、コメント |
| `/genres/[slug]` | ジャンル別一覧 | ジャンルの「良さ」一文、そのジャンルの記事一覧 |
| `/categories/[slug]` | 記事の種類別一覧 | 種類の切り替えチップ、記事一覧 |
| `/search` | タグ＋キーワード検索 | キーワード欄、記事の種類タグ、系統ごとのジャンルタグ、結果一覧。条件なしなら全記事 |
| `/about` | このサイトについて | コンセプト、年齢制限、紹介する作品の方針、コメントのルール |
| `/operator` | 運営者情報 | サイト名、URL、運営者（閨の主）、開設日、連絡方法、内容、対象、広告について |
| `/privacy` | プライバシーポリシー | 取得する情報、利用目的、第三者提供、コメントの確認、広告、免責、著作権、改定 |
| `/contact` | お問い合わせ | 名前、メール（任意）、種類、内容、同意チェック |

ヘッダーメニューとフッターから、このすべてのページへたどれるようにしてください。

## 機能仕様

各機能の見た目と動きは試作サイトに合わせてください。ここでは、試作だけでは分からない決まりごとを書きます。

### 年齢確認

- 初回アクセス時に、ページ全体に重ねて年齢確認を表示します（別ページへの転送はしない）。「18歳以上です（入場する）」を押すまで本文を操作できないようにします。
- 承認したらCookieに30日間保存します。「18歳未満です」を押した場合は、一般向けの外部ページへ移動します。
- 検索エンジンにも利用者と同じHTMLを返します（クローラーだけ別の内容を見せる処理は入れない）。
- ページ最上部に「このサイトは18歳以上の方を対象としています」の帯を常に表示します。

### ヘッダー

- 左にロゴ「人外ノ閨」とキャッチコピー、右に虫めがねとハンバーガーの2つのボタンを置きます。
- 虫めがねを押すと、パネルを挟まずに `/search` へ移動し、キーワード欄にカーソルを置きます。
- ハンバーガーは、系統ごとにカードで区切ったメニューを開きます（記事の種類、5つの系統と各ジャンル、サイト情報）。見出しはアクセント色、各項目は高さ40px以上で右端に「›」を付けます。

### トップページ

1. ヒーロー：「人外好きが、人外好きのために選ぶ。」「ヒトでは満たされない夜に。」「人ならざるものに心を奪われた人のために、刺さる作品を探して、本気で語るブログです。」と、記事の種類・タグ検索のチップ
2. 「はじめての方へ・特集」のスライド：指で左右にスワイプでき、矢印と丸ボタンでも切り替えられる。自動では動かさない
3. 新着記事：最新1本を大きく、その下に8本。下に「すべての記事を見る（件数）」ボタン
4. サイドバー（スマホでは本文の下）：人気の記事5本、系統ごとのジャンル一覧、書いている人

### 記事ページ

- 構成：パンくず → 種類・ジャンル・公開日 → タイトル → アイキャッチ → 本文 → 閨の主のひとこと → まとめ → 書いている人 → 関連記事3本 → コメント
- 関連記事は、同じジャンルを持つ公開済みの記事から選びます。入門ガイドは全ジャンルに関連します。
- `WorkBox`（紹介している作品の枠）は、作品名・サークル名・形式・ジャンルと、公式ページへの普通のリンクだけを表示します。段階Aでは画像・価格・アフィリエイトリンクは入れません。

### タグ検索

- 記事の種類のタグとジャンルのタグを、それぞれ複数選べます。
- 同じグループ内（種類どうし、ジャンルどうし）は「どれか」、種類とジャンルの間は「両方」で絞り込みます。キーワードはタイトル・説明・タグ名に対してすべての語を含むもので絞ります。
- 選んだ条件はURLのクエリに残し、共有やブックマークができるようにします。

### 診断

- 1問ずつ「はい」「いいえ」で答えます。上部に「Q3 / 7」と進み具合のバー、2問目以降は「ひとつ戻る」を表示します。
- 結果の相性（%）は、各結果について「獲得点 ÷ その結果が取りうる最高点」で計算します。
- 結果画面：いちばん合う結果をイラスト付きで大きく → 全結果の相性グラフ → 解説記事へのボタンとジャンル一覧へのチップ → Xでシェア → みんなの結果 → 「ひとつ戻る」「最初からやり直す」
- 相性グラフは、結果が3つ以上なら横棒グラフ（1位だけアクセント色）、2つなら左右の綱引きバーにします。
- Xでシェア：`https://x.com/intent/post` に「人外ノ閨の『◯◯診断』で、私は『◯◯』でした（相性◯%）」と `#人外ノ閨診断 #人外`、記事のURLを入れて開きます。
- みんなの結果：結果が出た時点で1回だけ、診断IDといちばん合った結果を記録します（同じ人の重複は、端末ごとに1日1回までに抑える）。集計は「みんなの結果を見る」を開いたときに取得します。

### コメント

- 名前（任意、空欄なら「名無しの人外好き」、20字まで）と本文（5〜400字）。
- 送信の流れ：ボット対策（Turnstile）→ 見えない入力欄が埋まっていたら破棄 → 同じ端末からの投稿は30秒あける → AIで内容を確認 → 問題なければ表示、問題があれば理由を伝えて表示しない。
- 表示しない内容：誹謗中傷・攻撃的な表現、URL・外部サイトへの誘導、電話番号やメールアドレスなどの個人情報、未成年を思わせる内容、同じ文字の過剰な繰り返し、露骨な性的描写。
- AIの判定に失敗したときは表示せず「保留」として保存し、管理人があとで確認できるようにします。

### お問い合わせ

- 名前（任意）、メールアドレス（任意、形式チェックあり）、種類（記事の内容／作品の掲載・紹介／削除・修正の依頼／その他）、内容（必須、2000字まで）、プライバシーポリシーへの同意（必須）。
- コメントと同じボット対策をかけ、送信内容はデータベースに保存し、管理人にメールで通知します。

## データベース設計（Supabase）

段階Aでデータベースを使うのは、利用者が書き込むもの3つだけです。記事・ジャンル・診断の中身はファイルで管理し、データベースには入れません。

| テーブル | 用途 | 主なカラム |
| --- | --- | --- |
| `comments` | 記事のコメント | id, article\_slug, name, body, status（published / rejected / pending）, reject\_reason, ip\_hash, created\_at |
| `contact_messages` | お問い合わせ | id, name, email, type, body, created\_at, handled（対応済みか） |
| `diagnosis_results` | 診断結果の集計 | id, diagnosis\_id, result\_key, client\_hash, created\_at |

- すべてのテーブルでRLSを有効にします。サイトから読めるのは「status が published のコメント」と「診断結果の件数の集計」だけです。
- 書き込みはすべて `app/api/` のサーバー処理から、service roleで行います。ブラウザから直接書き込ませません。
- `ip_hash` と `client_hash` は、連投や重複集計を防ぐためのもので、元のIPアドレスは保存しません。
- 段階Bで使う作品テーブル（`dmm_items` など）は、旧仕様書（土台編）を参照し、段階Aでは作りません。

## デザイン仕様と画像の方針

「閨」のコンセプトに合わせた、暗い夜の色調です。スマホ幅（390px）を優先して作り、PCでは本文の右にサイドバーを置きます。

| 名前 | 値 | 使いどころ |
| --- | --- | --- |
| bg | #15161B | ページの背景 |
| bg-deep | #0E0F12 | 年齢帯、フッター |
| surface | #1E2028 | メニュー、目次、診断、囲み |
| surface-2 | #262833 | メニュー内のカード、診断の見出し、ひとこと枠 |
| placeholder | #23252D | 画像がないときの枠 |
| line / line-strong | #2E313B / #41444F | 区切り線 / ボタンの枠 |
| text / text-sub / muted | #ECE9E2 / #CFCCC4 / #B3B0A8 | 本文 / 説明 / 補足 |
| accent / on-accent | #E2B45C / #1A1408 | ボタン、見出しの小ラベル、1位のグラフ / その上の文字 |
| danger | #F09A8A | エラー文 |

- フォント：見出しとロゴは Zen Old Mincho、本文は Zen Kaku Gothic New（`next/font/google`）
- 角丸：小さい部品8px、カード12px、チップは全丸
- タップできる部分は高さ44px以上、文字と背景のコントラストは4.5:1以上
- アイコンは線画のSVG。絵文字は使わない

### 画像

- 試作の画像はすべて、図形で描いた「仮イラスト」です。実装では、ジャンルごとの仮イラストをSVGコンポーネントとして用意し、記事の `eyecatch` や `Figure` に画像が指定されていればそちらを表示します。
- 管理人があとで用意する画像（画像生成AIで作ったもの、依頼したイラストなど）は `public/images/` に置くだけで差し替えられるようにします。WebP、遅延読み込み、`alt` 必須。
- 段階Aでは、販売サイトの作品画像は使いません。段階Bでも、作品のサンプル画像はレビューと作品カードにだけ使い、ジャンル解説の飾りには使いません。

## 守るべき要件とSEO

### 守るべき要件

1. **成人向けサイトであることの表明**：全ページの `<head>` に `<meta name="rating" content="adult">` を入れ、年齢確認と年齢帯を表示する
2. **紹介する作品の方針**：言葉と意思を持つ人外キャラクターが登場する作品だけを扱う。未成年を思わせる登場人物の作品、実在の動物を扱う作品、実在の人物を扱う作品は扱わない。この方針は「このサイトについて」にも明記する
3. **露骨な性的描写はしない**：記事は関係性・シチュエーション・キャラクターの魅力を中心に書く
4. **PR表記**：段階Aはアフィリエイトリンクがないため不要。ただし、作品をもらって紹介する記事を書く場合は、その記事に「PR」を表示できるよう、前付けに `sponsored: true` を用意しておく
5. **審査で見られるページ**：運営者情報、お問い合わせ、プライバシーポリシーを公開時点で必ずそろえる（プライバシーポリシーは下書きなので、公開前に実際のサービス名を入れて見直す）
6. **個人情報**：コメントとお問い合わせ以外で個人情報を取らない。IPアドレスは保存せず、ハッシュだけを使う

### SEO

- 記事タイトルに、検索される言葉（「人外 おすすめ」「獣人 同人」など）を自然に入れる
- 記事ごとに `description`（前付け）をメタ説明として出力する
- Xなどでシェアされたときの表示（OGP）：タイトル、説明、画像。画像は記事のアイキャッチ、なければサイト共通の画像
- `sitemap.xml` と `robots.txt` を自動生成する（公開日前の記事は含めない）
- 記事には構造化データ（Article、パンくず）を入れる

## 段階Bへの引き継ぎ

段階Bは、段階Aを作り直さずに「足す」形で進めます。そのため、段階Aの時点で次の3点を守ってください。

- `WorkBox` は、後から「サンプル画像・価格・セール表示・アフィリエイトリンク（PR）」を表示できる作品カードに差し替えられるよう、作品の属性を props で受け取る形にする（将来は `contentId` を渡すと作品データから埋まる）
- 記事のURL（`/articles/[slug]`）とジャンルslugは、段階Bでも変えない
- トップページは、セクションを部品単位で並べる作りにし、「新着作品」「セール中」「ランキング」を後から差し込めるようにする

段階Bで足すもの（作品データの自動収集、`dmm_items` などのテーブル、作品詳細・セール・ランキングのページ、PR表記）は、[旧仕様書（土台編）](https://claude.ai/artifact/5bStZaKc6U28K56XLcAfrw)と[最初の試作サイト](https://claude.ai/artifact/8bX8dbd4JRedXdRxb3Wp1y)をもとに、承認後に別の仕様書にまとめます。

## Claude Codeへの作業手順と完了条件

一度に全部作らず、次の順番で進めてください。各ステップの終わりでコミットし、`npm run dev` で動く状態を保ってください。

1. Next.js（App Router・TypeScript・Tailwind・ESLint）でプロジェクトを作り、ディレクトリを仕様どおりに整える
2. 色・フォント・角丸をTailwindのテーマに登録し、共通レイアウト（年齢帯、ヘッダー、メニュー、フッター、年齢確認、`rating` の meta）を作る
3. `content/data` のJSONと、MDX記事の読み込み（予約公開を含む）を作る。まず記事3本（入門ガイド、獣度、都市伝説・怪異）を試作から移す
4. トップ、記事、ジャンル別・種類別一覧、タグ検索のページを作る（仮イラストのSVGを含む）
5. 診断コンポーネント（点数計算、棒グラフ、綱引きバー、Xシェア）を作り、診断28個のJSONを試作から移す
6. 残りの記事28本をMDXに移す（`publishAt` は管理人があとで決めるので、仮に全部過去の日付でよい）
7. このサイトについて、運営者情報、プライバシーポリシー、お問い合わせのページを作る
8. Supabaseの3テーブルとRLS、コメント・お問い合わせ・診断集計のAPI、Turnstile、AIによるコメント確認を入れる
9. SEO（メタ説明、OGP、サイトマップ、robots、構造化データ）を入れる
10. READMEに「記事の追加・修正のしかた」「診断の直しかた」「画像の差し替えかた」「環境変数」を、プログラムを知らない人にも分かるように書く
