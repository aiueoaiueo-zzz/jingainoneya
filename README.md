# 人外ノ閨（じんがいのねや）

人外好きが、人外好きのために作品を選んで語る、成人向けのブログです。
いまは **段階A（語りブログ）** です。仕様は [`docs/spec-a.md`](docs/spec-a.md)、見た目と動きの見本は [`docs/prototype-a.html`](docs/prototype-a.html) にあります。

このREADMEは、プログラムを知らなくても運営できるように書いています。
**管理人がふだん触るのは `content/` フォルダと `public/images/` フォルダだけ**です。

## 1. ファイルの直し方（スマホでもできる）

GitHub のサイト上で、ファイルを直接直せます。

1. ブラウザで GitHub のこのリポジトリを開く
2. 直したいファイル（例：`content/articles/kaii.mdx`）を開く
3. 右上の鉛筆マーク（Edit）を押して書き換える
4. 「Commit changes」を押して保存する

保存すると、公開先（Netlify など）が自動でサイトを作り直します（数分かかります）。
書き方を間違えたときは、作り直しが失敗して**前の状態のサイトがそのまま残る**ので、壊れたサイトが公開されることはありません。失敗の理由は公開先の管理画面（Deploys）に日本語で出ます（[7. 困ったとき](#7-困ったとき)）。

> 新しいファイルを作るときは、フォルダを開いて「Add file」→「Create new file」を押します。

## 2. 記事の追加・修正のしかた

記事は `content/articles/` に **1本1ファイル** で置きます。ファイル名は `記事のURL名.mdx` です。

- 例：`content/articles/kaii.mdx` → `https://（サイトのURL）/articles/kaii` で表示されます
- URL名は半角の英小文字・数字・ハイフン（-）だけにしてください
- **一度公開した記事のURL名は変えない**でください（段階Bでも同じURLを使います）

### 記事ファイルの形

ファイルの先頭を `---` ではさんだ部分を「前付け」と呼びます。ここに記事の情報を書き、その下に本文を書きます。

```markdown
---
title: 都市伝説・怪異の魅力：日常の隣にいる「何か」に見初められる
slug: kaii
category: genre
genres: [kaii]
publishAt: 2026-11-20
description: 八尺様のような、条件がそろうと現れる正体不明の存在。怖さと引力の正体を語ります。
eyecatch: /images/eyecatch/kaii.webp
authorNote: 閨の主のいちばんの推しジャンルです。怖い夜ほど、なぜか読みたくなります。
---
ここから本文です。最初の段落は導入文になります。

## 見出し

本文……
```

| 項目 | 必須 | 書くこと |
| --- | --- | --- |
| `title` | ○ | 記事のタイトル。検索されやすい言葉（「人外 おすすめ」「獣人 同人」など）を自然に入れる。`[` で始まるときは `"` で囲む |
| `slug` | ○ | URL名。**ファイル名と同じ**にする |
| `category` | ○ | 記事の種類：`guide`（入門ガイド）、`genre`（ジャンル解説）、`talk`（語り・考察）、`matome`（おすすめまとめ）、`review`（作品レビュー） |
| `genres` | ○ | ジャンルのURL名を `[kemono, bird]` のように並べる（一覧は `content/data/genres.json`）。入門ガイド（`guide`）は自動で全ジャンル扱いなので書かなくてよい |
| `publishAt` | ○ | 公開日。`2026-11-20` の形。**この日の0時（日本時間）に自動で公開**されます |
| `description` | ○ | 記事の説明。一覧や検索結果、Xでシェアされたときに出ます（1〜2文） |
| `eyecatch` |  | アイキャッチ画像。なければ仮イラストが出ます（[4. 画像](#4-画像の差し替えかた)） |
| `authorNote` |  | 「閨の主のひとこと」。書くと「まとめ」の直前に自動で枠が入ります |
| `sponsored` |  | 作品をもらって紹介する記事なら `true`。記事に「PR」が表示されます |

### 予約公開

- `publishAt` が未来の記事は、一覧・検索・関連記事・サイトマップのどこにも出ません。URLを直接開いても「ページが見つかりません」になります
- その日の0時（日本時間）を過ぎると自動で公開されます。**ファイルを置いておくだけ**でOKです
- 運用の目安：1日1本、レビューを優先して解説と混ぜる

### 本文の書き方

| 書きたいもの | 書き方 |
| --- | --- |
| 見出し（目次に入る） | `## 見出し` |
| 小見出し（目次に入らない） | `### 小見出し` |
| 太字 | `**太字**` |
| 太字（「。」などで終わり、すぐ後に文字が続くとき） | `<b>太字。</b>` ← `**` だと太字にならないため |
| 箇条書き | 行の先頭に `- ` |
| 番号つきの箇条書き | 行の先頭に `1. ` |
| サイト内へのリンク | `[リンクの文字](/articles/kaii)` |
| サイト外へのリンク | `[リンクの文字](https://...)` （新しいタブで開きます） |

- **目次**は `##` の見出しから自動で作られます（「まとめ」は目次に入りません）。目次を別の場所に出したいときは、その場所に `<Toc />` と1行書きます
- 「閨の主のひとこと」は `authorNote` から自動で入るので、本文には書きません。見出しはちょうど `## まとめ` にしてください

### 記事の中で使える部品

| 部品 | 書き方 | 内容 |
| --- | --- | --- |
| 診断 | `<Diagnosis id="g_kaii" />` | はい・いいえの診断（id は `content/data/diagnoses/` のファイル名） |
| 図 | `<Figure art="kaii" caption="イメージ：都市伝説・怪異" />` | 仮イラスト。`art` はイラストの種類（ジャンルのURL名、`guide`、`moon`、`muzzle`） |
| 図（画像） | `<Figure src="/images/kaii-1.webp" alt="画像の説明" caption="図の説明" />` | 用意した画像を出す |
| 小さい図を横に並べる | `<FigureRow>` と `</FigureRow>` の間に `<Figure small ... />` を並べる | |
| 紹介している作品の枠 | `<WorkBox title="作品名" circle="サークル名" format="同人誌" genre="kemono" url="公式ページのURL" />` | 段階Aでは画像・価格は出ません |
| 囲み | `<Callout>コツや補足の文章</Callout>` | |
| 項目の並び（左に線） | `<ItemList>` と `</ItemList>` の間に `- **見出し** 説明` を並べる（前後に空行） | |
| 小さな補足文 | `<Note>補足の文章</Note>` | |
| 獣度のものさし | `<Scale />` | |
| 3つの軸の図 | `<Axes />` | |

部品の名前の大文字・小文字、`"`、最後の `/>` を正確に書いてください。

### 守ること

- 露骨な性的描写は書かない。関係性・シチュエーション・キャラクターの魅力を中心に書く
- 言葉と意思を持つ人外キャラクターが登場する作品だけを扱う。未成年を思わせる登場人物の作品、実在の動物・実在の人物を扱う作品は扱わない
- 段階Aでは、販売サイトの作品画像・価格・アフィリエイトリンクは載せない

## 3. 診断の直しかた

診断は `content/data/diagnoses/` に **1診断1ファイル**（`診断ID.json`）で置いています。全28個です。

| ファイル | 診断 |
| --- | --- |
| `entry.json` | 入門ガイド：人外の入り口診断 |
| `kemono.json` | 獣度診断 |
| `made.json` / `kaii.json` | 作られた存在タイプ診断 / 怪異タイプ診断 |
| `grp_beast.json` など5個 | 系統別診断（`grp_系統のURL名`） |
| `g_bird.json` など19個 | ジャンル別タイプ診断（`g_ジャンルのURL名`） |

### ファイルの形

```json
{
  "id": "grp_wafu",
  "title": "あなたの和風・怪異系診断",
  "chartLabel": "ジャンルごとの相性",
  "options": [
    {
      "key": "kaii",
      "name": "都市伝説・怪異",
      "short": "怪異",
      "image": "kaii",
      "description": "結果の説明文",
      "link": "/articles/kaii",
      "linkText": "都市伝説・怪異の解説記事を読む",
      "genres": ["kaii"]
    }
  ],
  "questions": [
    {
      "text": "相手の正体は、分からないままのほうがゾクゾクする？",
      "yes": { "kaii": 2 },
      "no": { "yokai": 1, "oni": 1 }
    }
  ]
}
```

| 項目 | 内容 |
| --- | --- |
| `title` | 診断の名前（Xのシェア文では先頭の「あなたの」を外して使います） |
| `chartLabel` | 相性グラフの見出し |
| `options` | 結果の一覧。`key` は結果の目印（英数字）、`name` は結果名、`short` はグラフ用の短い名前（なくてもよい）、`image` は仮イラストの種類、`description` は説明文、`link` と `linkText` は解説記事へのボタン（なくてもよい）、`genres` はジャンル一覧へのボタン（なくてもよい） |
| `questions` | 設問。`text` は質問文、`yes` と `no` は「はい」「いいえ」のときに各結果へ入る点数 |

### 点数の決まり

- 全員が同じ設問に答え、「はい」「いいえ」ごとに `yes` / `no` に書いた結果へ点数が入ります
- 相性（%）は「その結果がもらった点 ÷ その結果が取りうる最高点」です
- 結果が3つ以上なら横棒グラフ、2つなら左右の綱引きバーで表示されます
- `yes` / `no` の中には、`options` にある `key` だけを書いてください。ない `key` を書くと、作り直しのときに「〇問目に、結果にない key があります」と止まって教えてくれます

### よくある直し方

- **質問文を変える**：`"text"` の文章を書き換える
- **点数を変える**：`"yes": { "kaii": 2 }` の数字を変える
- **質問を足す**：`questions` の中に `{ "text": ..., "yes": {...}, "no": {...} }` を1つ足す（前の項目との間に `,` が必要）

JSON は `"` と `,` と `{ }` `[ ]` の対応に厳しい形式です。直したあと作り直しが失敗したら、まずそこを確認してください。

## 4. 画像の差し替えかた

画像は `public/images/` に置くだけで使えます。

| 使う場所 | 置き場所の例 | 設定 |
| --- | --- | --- |
| 記事のアイキャッチ | `public/images/eyecatch/kaii.webp` | 記事の前付けに `eyecatch: /images/eyecatch/kaii.webp` |
| 記事の中の図 | `public/images/kaii-1.webp` | 本文に `<Figure src="/images/kaii-1.webp" alt="画像の説明" caption="図の説明" />` |
| Xなどでシェアされたときのサイト共通の画像 | `public/images/og-default.png` | 同じ名前で上書き（横1200×縦630） |

- 書くときは `public` を付けず、`/images/...` から書きます
- 形式は **WebP** がおすすめです（軽くて速い）。アイキャッチは横長（16:9、例：横1280×縦720）
- `alt`（画像の説明）は必ず書いてください。画像が見えない人や検索エンジンが、画像の内容を知るために使います
- 画像は自動で「必要になったときに読み込む」設定になっています
- 画像を指定しないところには、ジャンルごとの仮イラスト（図形の絵）が出ます
- 段階Aでは販売サイトの作品画像は使いません。画像生成AI・イラスト依頼・フリー素材を使う場合は、そのサービスの規約で成人向けサイトでの利用が認められているか確認してください

## 5. そのほかの設定ファイル

すべて `content/data/` にあります。

| ファイル | 内容 |
| --- | --- |
| `site.json` | サイト名、キャッチコピー、トップの紹介文、自己紹介文（`authorIntro`）、人気の記事（`popular`：記事のURL名を5つ）、XのアカウントURL（`xUrl`） |
| `carousel.json` | トップの「はじめての方へ・特集」のスライド。`article` に記事のURL名、`label` に小さな見出し、`text` に一言 |
| `genres.json` | 5つの系統と20のジャンル。ジャンルごとに URL名（`slug`）、名前、「良さ」の一文（`good`）、仮イラストの種類 |
| `categories.json` | 記事の種類（5種類） |

- 人気の記事やスライドに、まだ公開日前の記事を書いても大丈夫です（公開日まで自動で隠れます）
- ジャンルの `slug` は記事のURLや検索に使っているので、**変えない**でください

## 6. 環境変数（秘密の設定）

APIキーなどの秘密の値は、コードに書かず、**公開先（Netlify など）の管理画面の「環境変数（Environment variables）」** に入れます。
項目の名前の一覧は [`.env.example`](.env.example) にあります（値は空です）。

| 名前 | 中身 | どこで手に入れるか |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | 本番のURL（例：`https://jingai-neya.com`） | 取ったドメイン |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase のURL | Supabase の Project Settings → API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 読み取り用の公開キー（anon） | 同上 |
| `SUPABASE_SERVICE_ROLE_KEY` | 書き込み用の秘密キー（service_role）。**絶対に公開しない** | 同上 |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | ボット対策のサイトキー | Cloudflare の Turnstile でサイトを追加 |
| `TURNSTILE_SECRET_KEY` | ボット対策の秘密キー | 同上 |
| `ANTHROPIC_API_KEY` | コメントのAI確認に使う Claude API のキー | Claude Console（console.anthropic.com） |
| `MODERATION_MODEL` | AI確認に使うモデル。空なら `claude-opus-5-5`。費用を抑えるなら `claude-haiku-5-5` など | 自分で決める |
| `HASH_SALT` | 長いランダムな文字列（40文字以上の英数字）。連投防止などに使う | 自分で作る。**一度決めたら変えない** |
| `RESEND_API_KEY` | お問い合わせ通知メールの送信キー | Resend（resend.com） |
| `CONTACT_NOTIFY_TO` | 通知を受け取るメールアドレス | 自分のアドレス |
| `CONTACT_NOTIFY_FROM` | 通知の送信元（例：`人外ノ閨 <noreply@jingai-neya.com>`） | Resend でドメインを認証して作る |

### 初めて設定するときの順番

1. **Supabase**：プロジェクトを作り、SQL Editor に [`supabase/migrations/20261105000000_stage_a.sql`](supabase/migrations/20261105000000_stage_a.sql) の中身を貼り付けて実行する（コメント・お問い合わせ・診断集計の表ができます）
2. **Cloudflare Turnstile**：サイト（自分のドメイン）を追加して、サイトキーと秘密キーを取る
3. **Claude API**：APIキーを作る。月の利用上限も Console で決めておく
4. **Resend**：ドメインを認証して、APIキーを取る
5. 上の表の値を、公開先の環境変数に入れて、サイトを作り直す

### 設定が足りないとき

- Supabase が未設定：コメント・お問い合わせ・みんなの結果は「いまは送信できません」と表示されます（記事や診断はふつうに動きます）
- Turnstile が未設定：本番ではコメントとお問い合わせを受け付けません（ボット対策なしで公開しないため）
- Claude API が未設定・失敗：コメントは「保留」で保存され、表示されません。管理人が確認して表示します（下記）
- Resend が未設定：お問い合わせは保存されますが、メール通知は届きません

### 保留・非表示のコメント、お問い合わせの確認

Supabase の管理画面の Table Editor で見られます。

- `comments`：`status` が `published`（表示中）、`rejected`（非表示。理由は `reject_reason`）、`pending`（保留）。保留を表示するときは `status` を `published` に変える
- `contact_messages`：お問い合わせ。対応したら `handled` にチェックを入れる
- `diagnosis_results`：診断結果の記録（みんなの結果の元）

## 7. 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 直したのにサイトが変わらない | 公開先の管理画面（Deploys）で作り直しが失敗していないか。失敗していれば、理由の文に書かれたファイルを確認 |
| 「publishAt は 2026-11-20 のような日付で書いてください」 | 前付けの `publishAt` の形 |
| 「slug とファイル名をそろえてください」 | 前付けの `slug` とファイル名が同じか |
| 「category は … のどれかにしてください」「genres に知らないジャンルがあります」 | 前付けの書き間違い |
| 「診断「〇〇」が見つかりません」 | `<Diagnosis id="〇〇" />` の id と、診断のファイル名が同じか |
| 公開日なのに記事が出ない | `publishAt` が日本時間の今日以前になっているか |
| 年齢確認をもう一度見たい | ブラウザの Cookie `jingai_neya_age_ok` を消す |

## 8. 開発者向けメモ

```bash
npm install
cp .env.example .env.local   # 必要な値を入れる（空でも記事・診断は動く）
npm run dev                  # http://localhost:3000
npm run build                # 本番用に作る（記事・診断の書き間違いもここで見つかる）
npm run lint
```

- Next.js 16（App Router）＋ TypeScript ＋ Tailwind CSS 4。Cache Components が有効
- 記事：`content/articles/*.mdx`（前付けは gray-matter、本文は @next/mdx）。読み込みと予約公開は `lib/articles.ts`
- 予約公開：公開済みの一覧は `use cache` で「次の0時（日本時間）」に期限切れになる（`cacheLife`）。0時を過ぎた最初のアクセスで作り直される。記事ページは `ensureStatic = "navigation"` で、公開前・存在しない記事に本物の404を返す
- 診断：`content/data/diagnoses/*.json`、計算は `lib/diagnosis.ts`
- コメント・お問い合わせ・診断集計：`app/api/*/route.ts`、テーブル定義とRLSは `supabase/migrations/`。書き込みはすべて service role。IPなどはハッシュにしてから保存
- コメントのAI確認：`lib/moderation.ts`（Claude API、構造化出力、拒否時のフォールバック `fallbacks: "default"`、12秒で打ち切り）
- 段階Bへの引き継ぎ：`WorkBox` は作品の属性を props で受け取る（将来 `contentId` で作品データから埋める）。記事URLとジャンルslugは変えない。トップはセクション部品を並べる作り（`app/page.tsx`）
- ホスティングで確認すること：0時の自動公開（Next.js のキャッシュの期限切れ）がその環境で動くか。動かない場合は、毎日0時に作り直しを起動する設定（定期実行）を追加する
